# 独立插件接口

AIPet 的插件不直接改写桌面、QQ、人格、记忆或密钥模块。插件以一个目录为边界，由独立 harness 管理生命周期。

## 最小结构

```text
plugins/my-plugin/
├── .aipet-plugin/
│   └── plugin.json
├── entrypoint.py
└── README.md
```

`plugin.json` 的最小清单如下：

```json
{
  "schema_version": 1,
  "name": "my-plugin",
  "version": "1.0.0",
  "display_name": "我的插件",
  "entrypoint": "entrypoint.py",
  "files": [".aipet-plugin/plugin.json", "entrypoint.py", "README.md"],
  "test_command": ["{python}", "-I", "-B", "{entrypoint}", "--selftest"],
  "health_command": ["{python}", "-I", "-B", "{entrypoint}", "--health"]
}
```

入口提供三个明确模式：

- `--selftest`：离线、有限时长的插件自检，不发送消息、不访问真实 API。
- `--health`：安装后健康检查，只验证依赖和运行边界。
- `--serve`：正式工作模式。具体协议由插件声明；AIPet MCP 插件使用标准输入输出。

## 自动投入

在项目根目录运行：

```text
python -m harness --root . list
python -m harness --root . auto plugins/aipet-mcp
python -m harness --root . run aipet-mcp -- --serve
```

`auto` 会依次校验清单、运行测试、生成带 SHA-256 清单的压缩包、解压到独立暂存目录、运行健康检查，最后才更新 `data/harness/registry.json`。旧版本目录不会被覆盖；任何一步失败都不会切换当前启用版本。`data/harness/` 是本机状态，仍由 `.gitignore` 排除。

插件命令在隔离子进程内执行，只传入 `AIPET_ROOT`、插件根目录和 UTF-8 设置；不会把 API key、人格文件或记忆内容复制到测试目录。插件自身仍应对写入、网络和外部进程保持最小权限。
