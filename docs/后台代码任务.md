# 后台代码任务

本地聊天窗口中的用户，或 QQ 中已认证的主人，明确要求写程序、运行代码、生成图片/报告/文件或反复调试时，模型会调用 `code_task`。任务在后台独立运行，不占用原消息的回复窗口；完成后回到发起它的本地窗口或 QQ 会话发送说明，并处理产物。

每个任务使用 `data/code_tasks/<任务编号>/` 作为工作目录。模型可以在这里使用 `fs_list`、`fs_read`、`fs_write`、`fs_mkdir`、`run_python` 和 `web_search`，会读取真实的标准输出、错误输出和文件变化后再决定是否继续。普通聊天不创建任务，未认证的 QQ 用户也看不到任务调度和 Python 执行工具。

在原本地会话或 QQ 会话里可以说“任务状态”“继续做……”或“取消任务”。两边使用同一个任务管理器和任务目录；任务状态和产物索引保存在被忽略的 `data/code_tasks/index.json` 中。进程重启后，正在运行的任务会标记为中断，主人继续说要求即可接着做。

本地窗口会把后台进度和完成说明直接显示在当前聊天中，并列出产物路径；QQ 会通过主动消息发送说明，并尝试上传产物。任务的所有权仍绑定发起它的本地会话或 QQ 会话，继续操作时应回到原入口。

第一阶段的目录边界属于 AIPet 工具层，不是操作系统级安全沙箱；执行器不会自动注入 API key。需要外部服务凭据时，模型会停下来向 bot 管理员说明需要哪一种凭据。具体生图服务适配和密钥网页录入留到后续阶段。
