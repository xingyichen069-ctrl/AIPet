# 人格、QQ 和 mood 的运行时调整

本次修改保存在 AIPet 项目的源码及公开默认资料中。更新代码后需要重启桌宠和 QQ 桥；人格、情绪文案和档位配置会在后续请求读取。

## 档位与上下文

- daily：关闭思考，temperature 1.25，frequency_penalty 0.4；不再要求固定 1–3 句。保留查询、记忆、心情、约定和陪伴工具，执行权限同时限制到实际暴露的列表。
- serious 及以上保留原推理档位。当前选中档位没有改动；当前若是 max，需自行切到 daily 才会使用上述采样。
- QQ 群与私聊默认跟随桌面。已有本群覆盖仍保留，在群内用 `/档位 跟随` 清除覆盖；在群内发送 `/档位 daily` 等只改本群，已认证主人在私聊中切档则修改全局档位。
- system 顺序为思考要求、记忆与任务上下文、人格。灵梦原创试声在独立的 `DIALOGUE.json`，作为 user/assistant 示例置于真实历史之前；不会存入真实聊天历史。常规真实历史最多 24 条消息，thunder 最多 80 条。
- QQ 历史通过角色消息传入，不再拼成最新 user 消息中的剧本。移除重复“不私密”等提示，保留发送与执行权限控制。

## 人格与心情文件

人格优先读取 `persona/characters/<id>/` 的私人副本，缺失时回退到 `persona_defaults/<id>/`。旧 `persona/SOUL.md` 只作为小日和的兼容来源。通用 `persona/BOUNDARIES.md` 或 `BOUNDARY.md` 仍可作为公共边界。

每个情绪方案使用 `MOODS.json`，格式例如：

```json
{"喝茶":{"feel":"闲下来","voice":"慢悠悠地接话，正事仍说清楚。","hours":2,"sample":["坐吧。"],"avoid":"不必每句话都提茶。"}}
```

在人格管理窗口的“情绪文案”页编辑当前人格的方案，下方下拉框可借用其他人格的方案；点击“保存”生效。借用方案只读，修改原方案需选择它所属的人格。绑定保存到 `data/persona_moods.json`。

小日和沿用 `data/mood.json`，其他角色的状态在 `data/moods/<id>.json`，历史和冷却互不影响。首次初始化保留旧 `data/mood_catalog.json` 的小日和文案。已有私人 MOODS 文件优先，不被默认模板替换。其他尚无专属文案的角色用中性状态提示；可在界面自定义，避免继承小日和的声音。换绑后不再注入与新方案不匹配的旧状态。已开始生成的一轮固定人格与情绪方案绑定。

## 旧安装迁移

公开默认文件更新不会覆盖已有私人 SOUL。普通更新请按[旧安装迁移](旧安装迁移.md)复制私人资料；下面是可选的旧格式候选导出工具，不是更新必做步骤。

从**与旧安装分开的新版代码目录**运行（Windows的python替换为该目录的 `.venv\Scripts\python.exe`）：

```sh
python tools/migrate_persona_runtime.py "/path/to/old/AIPet"
```

工具只读取旧安装中的相关人格文件，将候选、差异和校验清单写到**工具所在项目**的 `work/persona-runtime-candidates-*/`，不会写回旧目录。若旧安装就是工具所在目录，会拒绝导出，避免把工作文件放进原安装。

- `candidates/` 是待人工审阅的文件，`diffs/` 显示修改建议，清单记录来源与摘要；保留私人风格、自写段落和原文字节，不读取或改写thinking配置。
- 只对明确识别出的完整试声对话提出拆分建议。格式不完整、已有不同或损坏的DIALOGUE时跳过；缺失的情绪文案也只是候选。
- 候选不会自动应用。审阅后可在新版人格管理中选中原角色，直接编辑保存，或导入候选 SOUL 并确认覆盖；程序会备份旧 SOUL。想先比较时，使用“新建人格”再导入。单个 SOUL 不会带入 DIALOGUE/MOODS 等文件，不要将候选目录整包覆盖私人资料。
- 旧 `--apply` 参数现在明确报错退出，程序内的旧应用函数也拒绝执行。原“自动备份后改写、按清单回退”的流程已停用。

人格内容的取舍仍由使用者决定。本轮不重写私人边界、风格，也不把公开模板强行套到现有角色上。人格完整备份参见[备份与恢复](备份与恢复.md)。

## 灵梦双 pass 探针

```sh
python tools/probe_reimu_rewrite.py
python tools/probe_reimu_rewrite.py --live
```

默认只检查五组模拟输入的请求格式，不联网。`--live` 使用当前安装的 API 凭据：先生成一版，再只改写语气，记录两版输出和单次/总耗时到 `work/persona-runtime/reimu-rewrite-results.json`。只使用公开灵梦模板和模拟输入，不读取私人记忆、真实聊天或发送 QQ 消息，两次请求都没有工具。

双 pass 尚未接入日常对话。需人工比较事实是否保持、有没有新增虚构经历、语气是否自然及等待时间是否合适，不能仅凭请求成功认定效果更好。当前目录无模型凭据，未做在线质量或延迟实测。

## 主线兼容

本次整合保留 main 对 harness、插件实验室与扩展打包功能的撤回。对话准备层与隔离测试脚本独立保留，不依赖 harness。主线没有 code_task，daily 也不暴露该工具。
