# 备份与恢复

普通更新优先使用[README的新目录迁移](../README.md#从旧版本更新)，保留可直接打开的旧安装。本页是额外保存私人资料、找回某份人格或检查历史快照的方法。

## 先保存一份

退出桌宠及使用同一目录的其他程序。在项目文件夹的地址栏输入 `cmd` 并回车，再运行：

```bat
.venv\Scripts\python.exe src\backup.py create 手动保存
.venv\Scripts\python.exe src\backup.py list
```

便携安装使用 `runtime\python.exe`；Mac在项目终端使用 `.venv/bin/python`。成功后会显示 `backups` 内的ZIP名称。名称包含时间和唯一标识，连续保存也不覆盖前一份；失败不会把未完成的包当成成功快照。

| 默认保存 | 不包含或需要另行保留 |
|---|---|
| 人格库完整相对目录、SOUL/边界、当前选择、头像、示例对白、情绪文案 | 运行环境、代码、Live2D资源、自定义主题、外部文件沙箱 |
| 情绪绑定、各角色状态、旧情绪文案、外观和桌面草稿布局 | `secrets.json`、`qq_token.json` 等凭据文件及缓存 |
| 默认路径下的记忆时间线、档案、摘要、归档 | 知识库源文件与索引、历史备份目录；非常规自定义存储路径需另行核对 |
| 聊天与约定数据库的SQLite一致性快照、config与thinking | 不承诺备份所有可选QQ资料；QQ专项本轮暂缓 |

**普通备份仍是私人资料。** 它包含聊天、人格、记忆，`config.json` 还可能带有Tavily等内嵌key，不能因为未包含secrets就公开发送。目录迁移和普通备份的清单不同：迁移会带上密钥，普通备份不能代替新机的API配置。

## 默认恢复：先导出看看

用 `list` 找到需要的ZIP，将下面的示例名替换为完整文件名：

```bat
.venv\Scripts\python.exe src\backup.py restore "替换为list显示的完整文件名.zip"
```

程序先检查整个包的路径、文件校验和基本结构，再导出到新的 `backups/restored-*/` 目录。**当前安装的资料不会因此被更换。** 导出目录中的 `RESTORE_INFO.txt` 说明来源；它只有资料，不能当作完整安装启动。

如果只是找回旧人格，可在当前程序的“人格管理 → 导入SOUL”选择导出的文件。每次导入创建新副本，不自动设为当前；边界、头像与情绪不随单个SOUL导入，需要逐项核对和补回。

老包可能只有 `persona/SOUL.md`，没有新版 `characters` 库、当前选择或情绪。工具会提示这一点；导出成功不代表这些从未备份的内容被补回。

## 需要覆盖当前资料时

这是进阶操作。先退出所有使用本安装的程序，保留完整安装副本，再明确添加 `--in-place`：

```bat
.venv\Scripts\python.exe src\backup.py restore "替换为list显示的完整文件名.zip" --in-place
```

整个包校验通过后，会先保存 `prerestore` 安全快照及 `restore-before-*` 原文件清单，再覆盖包中的文件。数据库通过SQLite备份接口恢复，避免旧WAL把新恢复内容覆盖回去。目标被占用、路径经过符号链接/目录联接、包损坏或含不允许写入的文件时，会停止并说明原因。

只覆盖包中包含的文件，**包外资料不会删除**，所以这不是把整个安装精确回到某个历史时刻。仅含根SOUL的旧包遇到当前角色库时拒绝原地恢复，避免旧内容看似恢复了却没有作用于当前人格。使用默认导出，再按需要导入新副本。

捕获到写入失败时会尝试回退本次写入；若回退也失败，按提示保留安全快照、原文件与清单，先不要继续使用混合状态。断电或强制结束不保证自动回退，不要因此删除旧安装。

成功后重新启动，检查当前人格、边界、情绪、历史话题、草稿和约定，再发送一条实际对话。恢复历史快照可能带回后来已经撤回的内容，应根据自己的需要核对。

## 自动备份的保留规则

`backup.py auto` 会创建快照并按现有规则只保留最近30个ZIP，包含手动创建的ZIP；长期想保留的快照请另存到安全位置。普通 `create` 不清理旧包，默认导出的目录也不属于这项ZIP清理。
