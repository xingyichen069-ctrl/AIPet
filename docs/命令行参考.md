# 命令行参考

所有脚本都能单独跑，不依赖桌宠窗口。带 `selftest` 的可以直接验证自己那份装好没有。

把 `python` 换成你实际用的解释器 —— 便携版是 `runtime\python.exe`，源码安装是 `.venv\Scripts\python.exe`（Windows）或 `.venv/bin/python`（macOS）。

python src/brain.py check             # 验证连通性

python src/brain.py ask "深入分析…" --level deep --show-reasoning

退不掉的时候从外面停（平时用右键 → 退出就够了）：

```bash
python src/app_entry.py status        # 在跑没
python src/app_entry.py stop          # 源码版杀掉 + 清锁文件
AIPet.exe stop                        # 便携版同一入口
```

什么时候会需要它：鼠标穿透开着点不到窗口、
托盘图标被 Windows 11 收进折叠区、或者事件循环本身僵住。

## 看运行状态

```bash
python src/app_entry.py status              # 打一次（桌宠 + QQ 桥）
python src/app_entry.py status --log 40     # 顺便打 QQ 日志最后 40 行
```

它**只读**，不启停任何东西。最值得看的是两条告警：

- **锁文件在、进程已经没了** —— 桌宠上次没正常退出
- **状态文件里的 PID 和实际在跑的对不上** —— QQ 桥被杀掉时来不及写「我停了」，
  那份状态是上一个进程留下的，网关那一行不能信

## QQ

```bash
AIPet.exe qq status     # 在跑没、连上没
AIPet.exe qq start
AIPet.exe qq stop
AIPet.exe qq restart    # 改完代码重启
```

详见 [QQ 接入](QQ机器人接入提示词.md)。

## 更新与迁移

```bash
AIPet.exe prepare                         # 检查便携 runtime，或准备源码 .venv
AIPet.exe memory show                      # 查看记忆

python src/update.py                         # 查有没有新版本
python src/update.py selftest                # 检查版本比较、压缩包安全和 GitHub
python src/update.py update --yes            # 下载并安装最新 tag
python src/update.py update --branch all-round --yes  # 安装指定分支
python src/update.py update --package <完整发布包.zip> --yes  # 安装便携整包

AIPet.exe migrate <旧目录> --dry-run   # 只看迁移清单
AIPet.exe migrate <旧目录>             # 看清单并确认

AIPet.exe migrate <旧目录> --with-runtime   # 连 runtime/ .venv/ 一起拷
```

带 `release-manifest.json` 的便携目录只能用完整发布包更新。整包会在独立暂存目录完成清单、哈希和运行时导入检查，再等待桌宠与 QQ 自行退出；失败时按 `backups/package-update-*/transaction.json` 恢复。

`--with-runtime` 是给**同机换目录**用的。`runtime/` 是嵌入版 Python，里面全是相对路径，换个盘符照样跑 —— 直接拷能省一次 300 MB 下载。`.venv/` 相反：`pyvenv.cfg`、`Scripts` 里的 shebang、`*.pth` 都写死了绝对路径，拷过去多半要重建，脚本会为它多打一句警告。

不带这个参数时 `runtime/` 会被列进「不搬」，新装里运行一次 `AIPet.exe prepare` 就行。

开搬之前，脚本会检查旧装里那个 QQ 桥还在不在跑 —— 它是脱离进程组的，关窗口关不掉，换完装两个网关会挂在同一个 bot 上，事件随机分给其中一个，群里就会重复回。找到了先停掉，再拷文件（反过来的话旧桥可能在拷的过程中往 `journal.jsonl` 追一条，拷到一半的文件是断的）。不想让它动就加 `--keep-old`。

它不会照着 `data/qq.pid` 直接杀 —— PID 会被系统回收，那个文件可能已经旧到数字分给了别的进程，所以要先核对命令行里确实写着旧目录的路径。

## 自检

**只有下面这些脚本认 `selftest` 这个子命令**，别的（`memory.py`、`thinking.py`、`knowledge.py` 等）传进去只会打一段帮助，不会跑任何检查 —— 退出码是 0，看起来像通过了，其实什么都没做。

```bash
python src/local_tools.py selftest
python src/mood.py selftest
python src/people.py selftest
python src/qq_text.py selftest        # 平台限制兜底（纯函数）
python src/qq_bot.py selftest         # 协议编解码、去重、token 缓存，不联网
python src/qq_bridge.py selftest      # 灌假事件，不联网
python src/vision.py selftest         # 真调一次视觉接口，需要配好
python src/docx_read.py selftest      # 现造一份 docx，含读里面的图
python src/update.py selftest         # 真连一次 GitHub
AIPet.exe migrate selftest             # 造两个假安装真搬一遍
```

界面和集成测试在 `tests/`，走 unittest：

```bash
python -m unittest discover -s tests        # 67 项
```

`tests/` 里的文件**不能单独跑**（`python tests/test_appearance.py` 什么都不执行、直接退出 0）—— 它们要 `discover` 才能被发现。想单独验证一个用例：

```bash
python -m unittest discover -s tests -v 2>&1 | grep 用例名
```

`tests/test_desktop.py` 里两个滚动条测试在 offscreen 平台下会**随机失败**（布局没跟上就断言了），与改动无关。
