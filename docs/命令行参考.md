# 命令行参考

普通使用请按 [README](../README.md) 的双击入口。以下示例适用于在项目根目录打开的Windows命令提示符cmd；不要在任意目录直接复制。PowerShell运行带引号的解释器路径时需在前面加 `&`。

源码安装使用 `.venv\Scripts\python.exe`，便携安装替换为 `runtime\python.exe`；Mac用 `.venv/bin/python`。不要假设只安装uv后系统就有裸python命令。

## 配置与大脑

```bat
.venv\Scripts\python.exe tools\first_run.py configure
.venv\Scripts\python.exe tools\first_run.py check
.venv\Scripts\python.exe src\brain.py check
.venv\Scripts\python.exe src\brain.py ask "你好"
.venv\Scripts\python.exe src\brain.py ask "帮我分析这个设计" --level deep
.venv\Scripts\python.exe src\brain.py chat
```

前两个是本地配置操作。brain的check/ask/chat会调用真实API，可能计费；check只验证省电档的一条短回复，不证明max或所有工具可用。`setkey`仍可用，但会把key放进命令历史并立刻联网验证，新手优先编辑文件。

## 档位与记忆

```bat
.venv\Scripts\python.exe src\thinking.py list
.venv\Scripts\python.exe src\thinking.py set deep
.venv\Scripts\python.exe src\thinking.py auto "帮我分析这个设计"
.venv\Scripts\python.exe src\thinking.py params
.venv\Scripts\python.exe src\memory.py stats
.venv\Scripts\python.exe src\memory.py search "报告"
.venv\Scripts\python.exe src\render.py --open
.venv\Scripts\python.exe src\consolidate.py status
.venv\Scripts\python.exe src\consolidate.py brief
```

`memory.py add/demo/compress`会改资料，`consolidate.py done`会推进整理游标。不要为了“测试安装”运行它们；压缩检索链路和整理游标问题仍待修复。不要将 `brief|done|status` 当成一条命令，竖线在shell中表示管道。

## 搜索、图片、文档和本地工具

```bat
.venv\Scripts\python.exe src\tools.py search "查询词" -n 5
.venv\Scripts\python.exe src\tools.py fetch https://example.com
.venv\Scripts\python.exe src\knowledge.py build
.venv\Scripts\python.exe src\knowledge.py search "查询词"
.venv\Scripts\python.exe src\knowledge.py stats
.venv\Scripts\python.exe src\local_tools.py get_time
.venv\Scripts\python.exe src\vision.py 看图 "D:\资料\截图.png"
.venv\Scripts\python.exe src\docx_read.py 看 "D:\资料\报告.docx"
```

搜索会联网，含图片的读取会调用视觉API；模型名、额度与费用以服务商为准。knowledge默认关闭；手动build后启用config中的knowledge.enabled并重启，才接入默认桌面/普通brain对话。文件变动或旧版索引需要重新build，详见[工具指南](工具与沙箱.md#本地知识库)。`local_tools.py`不接受selftest，空参数会轮流测工具并可能联网/改资料，日常检查不需要运行。

## 桌面与排查

双击“启动诊断.bat”可在控制台查看启动问题。也可用项目解释器运行 `src\pet.py --show-chat`。平时通过角色菜单或托盘退出；现有外部强制停止工具的PID核验问题暂未修复，不将强制停止作为新手更新步骤。

`src/proxy.py` 和 `src/proxy.py test` 会重新检测并实际访问网络，检测通过只说明检测站点可达；桌面可用右键 → 高级 → 重新检测代理。`src/proxy.py git`会修改Git全局代理，不是安装所需步骤。

## 更新

推荐在新目录运行：

```bat
.venv\Scripts\python.exe tools\update_wizard.py
```

会打开旧目录选择窗口，不猜测邻近安装、不自动结束进程、不搬运行环境。旧目录保留，先迁移再启动。详见 [README更新流程](../README.md#从旧版本更新)。

高级命令行预览仍可用：

```bat
.venv\Scripts\python.exe tools\migrate.py "D:\AIPet-old" --dry-run --keep-old
```

双击向导和原 migrate 命令行的预检与进程处理不同，详见[旧安装迁移](旧安装迁移.md)。命令行实际迁移默认尝试停止旧 QQ，`--keep-old` 跳过该路径；使用者仍需自行确认旧程序已退出。`--dry-run` 不复制或停止进程。`--force`、`--with-runtime` 不是新手推荐步骤；复制旧 venv 也不能保证新目录环境可用。原检查更新工具会取全仓标签，main 用户使用 README 给出的 main 下载链接。

## 备份、恢复和人格格式候选

```bat
.venv\Scripts\python.exe src\backup.py create 手动保存
.venv\Scripts\python.exe src\backup.py list
.venv\Scripts\python.exe src\backup.py restore "替换为list显示的完整文件名.zip"
.venv\Scripts\python.exe tools\migrate_persona_runtime.py "D:\AIPet-old"
```

`restore` 默认只导出到独立的 `backups/restored-*/`，不更换当前资料；仅明确加 `--in-place` 才原地覆盖，需先退出所有使用该目录的程序。恢复前校验整个包并做安全快照，包外资料保留，因此不是逐文件回滚到历史时刻。旧根SOUL包不能覆盖当前角色库，操作与隐私边界见[备份与恢复](备份与恢复.md)。

`migrate_persona_runtime.py` 应从独立新版代码目录运行，只在工具所在项目的 `work/persona-runtime-candidates-*/` 导出候选与差异，原 `--apply` 已停用；不改源安装、当前档位或人格正文。它与普通更新向导用途不同。

## 隔离测试

```bat
.venv\Scripts\python.exe tools\test_core.py
.venv\Scripts\python.exe tools\test_core.py test_onboarding
.venv\Scripts\python.exe tools\test_core.py test_companion.Services.test_chinese_duration
```

这会在项目work目录复制公开代码/模板，使用合成资料并拦截常规Python socket连接（不等于系统级网络隔离）。它比直接在自己的安装运行旧selftest更适合检查代码。测试数量由实际发现决定，不再手写固定数量；过滤输出不是只运行一个用例。

其他自检入口可能联网、写数据，部分旧自检还依赖作者私人档案/旧接口，未在本轮修复。通过离线测试不代表真实API、QQ、托盘或每个平台已经可用。

## QQ

内置 QQ 通道无需 Cherry Studio 或外部 MCP。先按[QQ 接入](QQ机器人接入提示词.md)填写凭据，日常使用“启动QQ.bat”和“停止QQ.bat”。下面在 Windows 项目目录的命令提示符中运行；完整便携环境把解释器换成 `runtime\python.exe`。

```bat
.venv\Scripts\python.exe tools\qq_ctl.py status
.venv\Scripts\python.exe tools\qq_ctl.py start
.venv\Scripts\python.exe tools\qq_ctl.py stop
.venv\Scripts\python.exe tools\qq_ctl.py restart
.venv\Scripts\python.exe src\people.py claim
```

`status` 查看进程与网关状态；`start/stop/restart` 控制独立 QQ 进程；`claim` 生成本机身份认领口令。更新代码或凭据后需重启对应目录的 QQ。只查看状态不会启动它，进程存在也不等于已连接或能回复。

Windows 可选开机自启：

```bat
.venv\Scripts\python.exe tools\qq_ctl.py install
.venv\Scripts\python.exe tools\qq_ctl.py uninstall
```

两条命令分别创建和移除启动文件夹中的“小日和 QQ.lnk”；不代表当场启动或停止 QQ。换目录后应在新目录重新设置并检查目标路径，避免登录时又启动旧版。

旧 QQ selftest 会触及运行资料，不再作为新用户的连接检查步骤。开发者使用前述[隔离测试](#隔离测试)，真实接入则以连接状态和实际一条回复确认。
