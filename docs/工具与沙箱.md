# 工具、沙箱与外部服务

她除了说话，还能做一些事。这个文档讲她能做什么、边界在哪、以及要开哪些开关。

## 她手上的工具

实现在 `src/local_tools.py`。daily只开放get_time、recall、remember、mood、web_search、agreement、quiet_company；文件/系统/视觉工具并非每个档位都可用。

Windows命令示例中的python请替换为项目 `.venv\Scripts\python.exe`；便携安装用 `runtime\python.exe`。首次配置使用README的双击入口。

| 工具 | 作用 |
|---|---|
| `agreement` | 创建、查看和处理约定 |
| `quiet_company` | 安静陪伴计时 |
| `get_time` | 当前日期时间、星期 |
| `get_system` | 电量、开机时长、系统 |
| `recall` | 检索记忆库 |
| `remember` | 写入记忆库 |
| `web_search` | 联网搜索（省电档关闭） |
| `mood` | 心理点：`get` / `list` / `set` / `clear` / `log` |
| `fs_list` `fs_read` | 列目录、读文件（纯文本和 **.docx**） |
| `fs_write` `fs_mkdir` | 写文件（可追加）、建目录 |
| `see_image` | 看图片 |
| `keep_image` | 把 QQ 发来的图存进沙箱，免得被定期清理 |

## 读 Word 文档

`fs_read` 和对话窗附件都认 **.docx**，会掏出两样东西：

- **正文** —— 段落、表格、换行、制表符，按原顺序
- **文档里的图片** —— 交给视觉接口读成文字，按正文或表格单元格内的引用顺序插入；同一内嵌图片重复出现时复用识别结果

第二样是关键：报告和作业里常把截图、扫描件直接贴在正文中间，只解析 XML 是拿不到那些字的。

桌面会在后台读取，显示“正在读取”，可点附件标签取消；读取期间不能发送该材料。移除、替换、切换话题或退出后，迟到的结果会丢弃，不会写进另一个话题。已经发出的视觉请求可能仍会计费。

**任一必需图片失败，整份Word就不添加。** 未配置视觉接口、空识别结果、接口截断、图片缺失或外链图片都明确失败；不把接口报错保存成材料，也不偷偷发送只读到的一部分。纯文字Word无需视觉接口。每个文件只解析一次，每张不同图片只识别一次；没有位置信息的媒体会明确标注“按文件顺序列出”，不声称还原页面排版。

| 限制 | 超出后如何处理 |
|---|---|
| DOCX文件32 MB、解压总量64 MB、内部文件4096个 | 拒绝并提示拆分 |
| 单个XML/关系文件4 MB、单张图片8 MB | 拒绝并提示简化文档或缩小图片 |
| 最多12张不同图片 | 拒绝整份文档，不只读取前12张 |
| 桌面图文主体24,000字符；命令行/共享读取器120,000字符 | 拒绝并提示拆分，不截取前半份；文件名标题不计入主体上限 |

这些是本程序的读取限额，视觉服务还可能有更低的限制。遇到不支持的图片格式（如EMF/TIFF），先在Word中换成PNG/JPG等支持格式。

**不用装 `python-docx`。** docx 本身就是个 zip，里面几个 XML，标准库的 `zipfile` + `ElementTree` 够用了。

读不了的：

| 格式 | 为什么 |
|---|---|
| `.doc` | 老的二进制格式，不是一个 zip，解不出来。她会回一句让对方另存为 .docx |
| `.pdf` | 另一套东西，没做 |
| `.xlsx` `.pptx` | 结构类似，但没做 |
| 批注、修订痕迹、页眉页脚、脚注 | 正文之外的部分先不管 |

手动读取会调用已配置的视觉服务，可能计费：

```bat
.venv\Scripts\python.exe src\docx_read.py 看 "D:\资料\报告.docx"
```

开发者离线检查用 `tools/test_core.py test_attachments`，其中视觉结果由合成响应提供。

## 沙箱：她能碰哪些文件

`fs_*` 四个工具**只能动沙箱根里面的东西**。这是代码层拦的，不是靠她自觉。

沙箱根默认是**用户主目录下的 `AIPet` 文件夹**（Windows 上是 `%USERPROFILE%\AIPet`，macOS 上是 `~/AIPet`）。想让她管别的地方 —— 比如你专门放资料的盘 —— 改 `data/config.json`：

```json
{
  "tools": {
    "fs_root": "D:\\我的资料"
  }
}
```

这里只修改现有tools对象中的fs_root，不用这段示例替换整份config。留空就是默认值；这个字段下次工具使用时读取。

**这是最该按自己习惯设的一项。** 设成哪里，她就能读、能写、能建目录到哪里；设窄一点更安全，设成你日常用的资料目录更方便。

### 拦得住什么

路径先 `resolve()` 再验归属，所以下面这些都会被拒：

```
../../../secrets.json                 → 被拒
读取/../../../AIPet/data/secrets.json  → 被拒（合法根 + 用 .. 钻出去）
//?/C:/Windows                        → 被拒（设备路径）
D:/其他目录/x.txt                      → 被拒（带盘符且不在沙箱内）
```

第二行是真正难防的：路径以合法根开头，靠 `..` 往外钻。只做字符串前缀比较是拦不住的，必须先解析成真实路径再验。

带盘符的绝对路径不在沙箱里时会**明确拒绝**，而不是剥成相对路径 —— 否则你说的「存到 D:\其他目录」会悄悄变成「存到沙箱里」，你按自己说的路径去找什么都找不到。

普通文本文件的单次读写上限为20万字节（`FS_READ_MAX` / `FS_WRITE_MAX`）；DOCX读取按上文Word限制处理。限制大文件是为了避免一次读入过多内容。

### 看图不受沙箱限制

`see_image` 可以看这台电脑上**任何位置**的图片。理由是从对话窗拖进来的文件本来就在各处（桌面、下载、截图文件夹），限制在沙箱里等于让拖图残废一半。

它靠另外两道闸门把关：

- **后缀白名单** —— 不是图片一律拒
- **文件头魔数** —— 后缀能改、内容改不了。文本改名成 `.png` 也过不去

这两条不是「顺手校验一下」，是必须的：读图会把**整份文件** base64 编码后发到视觉接口，没有它们，`see_image("secrets.json")` 读不出内容但密钥已经出门了。

第二条是实测出来的 —— 只装后缀检查时，把文本改名成 `.png`，**内容真的发出去了**（服务器报 400 是它自己解析不了，不是被拦下的）。

## 配一个视觉接口

她自己的脑子是纯文本的，图进去只能干看着。`src/vision.py` 负责把图读成文字，**不绑定任何一家服务**。

只要对方是 OpenAI 兼容的 `/chat/completions`，并且支持 `image_url` 这种消息格式，就能接：

| 场景 | 例子 |
|---|---|
| 本机跑 | Ollama、vLLM、LM Studio —— 图不出本机 |
| 云上 | 各家多模态 API |
| 学校 / 公司部署 | 自己的内网 endpoint |

先双击“配置API.bat”打开已经生成的 `data/secrets.json`，只填写其中三个视觉字段，保留已有大脑密钥和其他字段。下面是字段示意，不是替换整份文件：

```json
{
  "vision_base_url": "https://你的服务/v1",
  "vision_api_key": "对方的 key",
  "vision_model": "服务商提供的一个视觉模型名"
}
```

如果你使用的本地服务明确不校验key，可填一个非空占位值；云服务按提供者要求填写。没有配置时返回明确错误，桌面不会添加失败材料。接口返回成功只代表收到文字，识别准确性仍需核对。

```bash
python src/vision.py            # 自检：现场造一张有字的图，真调一次
python src/vision.py 看图 <路径>
```

**配之前先想清楚图会发到哪里。** 读图是把整份文件 base64 编码后 POST 出去的：本地模型不出机器，云服务就是出门了。QQ 群里别人发的图走的是同一条路。

## 联网搜索

```bash
python src/tools.py search "查询词" -n 5
python src/tools.py search "今日新闻" --news
python src/tools.py fetch https://example.com
python src/tools.py cache --clear
```

| 后端 | 额度 | 要 key 吗 | 说明 |
|---|---|---|---|
| `ddgs`（默认） | 取决于上游限流 | 不要 | 聚合 bing / brave / google / duckduckgo |
| `tavily` | 以服务商当前方案为准 | 要 | 返回 LLM 就绪的摘要 |
| `searxng` | 取决于实例 | 取决于部署 | 完全自主，需要自己部署 |

在 `data/config.json` 已有的 `tools` 对象中修改 `search_backend`、`proxy` 等字段，保存后退出并重启。Tavily还需在同一对象填入 `tavily_key`，SearXNG需填 `searxng_url`；不要用局部示例替换整份配置。

| `proxy` 的值 | 搜索、网页读取和检查更新的行为 |
|---|---|
| `"auto"`（默认，也可留空） | 验证Windows系统代理和本机常见端口，按来源顺序选择能通过检测的地址；首个端口无效会继续找，没有可用地址时直连 |
| `"http://127.0.0.1:7890"` 等完整地址 | 始终使用这个地址；端口必须按自己的代理工具填写，失败会提示，不自动改成直连 |
| `"off"` | 这些请求直接连接目标，不使用系统或环境变量中的代理；系统级VPN/TUN仍由系统控制 |

手填地址支持 `http://`、`https://`、`socks5://` 和 `socks5h://`。常见代理工具通常给的是HTTP混合端口；不要因为想访问HTTPS网页就把HTTP代理地址改成 `https://`，后者要求代理本身支持TLS。SOCKS5h让代理解析目标域名。使用本机SearXNG等本地服务时，可选择 `off`；显式代理不会被 `NO_PROXY` 环境变量绕过。

自动检测没有找到代理时，10秒后下一次使用会重新找；找到的地址最多缓存60秒。打开或切换代理工具后，可在桌宠右键 → 高级 → **重新检测代理** 立即刷新。改了配置文件仍需重启；刷新按钮只重新检测当前已经读入的配置。

检测通过只表示 `https://www.google.com/generate_204` 可达，不能保证每个搜索服务都有结果；错误状态、跳转或返回登录/拦截页不算成功。手填地址的检测失败也不会改写配置，实际搜索仍会尝试该地址。检测站点本身可能暂时不可用，可结合实际查询判断。

Windows排查命令（便携安装把解释器换成 `runtime\python.exe`）：

```bat
.venv\Scripts\python.exe src\proxy.py
.venv\Scripts\python.exe src\proxy.py test
.venv\Scripts\python.exe src\tools.py search "Python 官方文档"
```

检测和查询会联网，状态输出隐藏代理账号密码。这套设置只管搜索、网页读取和检查更新；大脑、视觉等其他网络调用仍有各自的实现。无需运行会修改Git全局配置的 `proxy.py git`。

**缓存**是省额度最有效的手段：同一个 query 在 TTL 内不重复请求。默认 general 1 小时 / news 15 分钟 / 网页 24 小时，都在 config 里调。

旧环境曾观察到 `ddgs` 的news后端超时或无结果，这不是所有网络的当前结论。`tools.py` 会自动退回 text，并加一周内的时间过滤。

## 本地知识库

默认关闭。需要长期参考资料时：

1. 在项目根目录建立 `knowledge` 文件夹，放入UTF-8的 `.txt` 或 `.md` 文件。
2. 在项目目录运行下面的 `build` 命令，看到建索引成功；`search` 可预览命中，`stats` 查看状态。
3. 编辑现有 `data/config.json` 的 `knowledge` 对象，把 `enabled` 改为布尔值 `true`（不要写成带引号的字符串），退出并重启桌宠。
4. 询问与资料相关的问题。默认桌面对话和普通 `brain.py` 命令行会附带文件名、块位置和相关片段，将它们标作参考资料。不是每个问题都会命中，也不会自动写成人格或长期事实。

```bat
.venv\Scripts\python.exe src\knowledge.py build
.venv\Scripts\python.exe src\knowledge.py search "查询词"
.venv\Scripts\python.exe src\knowledge.py stats
```

资料默认独立预算 `knowledge.token_budget=2000` 估算tokens、`max_chunks=6`，包含来源和提示，不占用相关记忆的预算，也不代表整次请求上限。仅需改现有对象的相应值，不必用新模板覆盖配置。

新增、修改或删除资料后需重新 `build`；旧版索引也需重建。缺失、损坏或过期时，该轮不会注入旧片段，会在参考资料状态中说明原因，命令行也可查看，聊天本身仍可继续。此轮没有自动监听和后台重建。

**命中片段会随问题发送给你配置的大脑API。** 关闭时默认对话不读取/注入知识库；QQ等自定义system路径本轮不自动追加。采用关键词检索，效果取决于资料和查询；当前对话的一次性材料仍可直接作为附件发送。

## 接协议细节

两件容易踩的事，改代码时会碰到：

- 当前适配会保留工具轮的reasoning_content，满足相应推理接口的回传要求；不能推广成所有OpenAI兼容服务都要求这个字段。
- 工具调用会有多轮「思考 → 调用 → 再思考」，`max_tokens` 要留够，否则会在中途被截断。`MAX_TOOL_ROUNDS` 现在是 10。
