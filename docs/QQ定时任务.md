# QQ 定时任务

定时任务需要自行配置数据，默认对所有群关闭。主人在需要的群里开启后，按模板指定的北京时间发送。各群的开关与轮换进度独立，保存后重启仍保留。

## 在群里使用

发送时实际 @机器人，再输入指令：

| 指令 | 用途 |
|---|---|
| `/符卡 开启` | 从下一个时段开始在本群推送 |
| `/符卡 关闭` | 关闭本群推送；已提交给 QQ 的消息无法由开关撤回 |
| `/符卡 状态` | 查看开关、发送时间、最近结果和 QQ 错误码 |
| `/符卡 预览` | 查看下一张的排版，不推进轮换进度 |
| `/定时任务 列表` | 查看已安装的模板 |
| `/定时任务 开启 spellcards` | 按模板名称开启，关闭、状态和预览同理 |

只有已经绑定的主人可管理。指令只影响当前群，不接受在私聊中指定别的群。普通群消息即使写了这些文字，也不会触发开关。

## 任务数据与发送样式

任务 JSON 和对应 Markdown 放在本安装的 `data/qq_tasks/`，由使用者自行配置，不随源码分发。初始化只创建目录，代码更新不会覆盖已有数据。没有任务数据时，不会发送定时消息。

开关、轮换位置和最近发送结果保存在 `data/qq_schedules.json`；不要删除它来重置进度，否则会丢失去重记录。修改前先备份任务目录和状态文件。

## 扩展模板

例如新建 `data/qq_tasks/example.json`：

```json
{"schema":1,"id":"example","title":"示例卡片","kind":"cards","timezone":"Asia/Shanghai","times":["10:00"],"catalog":"example.md"}
```

再创建同目录的 `example.md`：

```markdown
| 符卡 | 持有者 | 解说 |
|---|---|---|
| 示例卡片 | 示例人物 | 今日卡片 |
```

用 `/定时任务 列表` 查看，然后在目标群执行 `/定时任务 开启 example`。`/符卡` 是名为 `spellcards` 的任务快捷命令，需要先配置对应任务。

卡名逐字竖排，末尾标注持有者；引号和短横线转为竖排字符。“解说”作为开头，可用 `<br>` 分成两行。修改 JSON 的 `times` 可调整每日时段，格式为 `HH:MM`；下次检查读取，无需重启。

模板只声明时间与纯文本卡片，不执行脚本、命令或文档中的指令。模板最多 8 个，每个最多 6 个时段；卡片文档最多 300 条、128 KiB，最多管理 32 个群。

## QQ 权限和发送边界

使用官方主动消息接口，不需要当时有人 @机器人。QQ 客户端的主动消息开关、群禁言、机器人权限和平台限频仍然有效；允许接收全部群消息不等于允许主动发送。

接口返回无权限、已非群成员或被禁言时，会暂停该群对应任务；处理好权限后重新执行开启指令。其他失败记下结果，不在同一时段反复重试。“QQ 已受理”表示接口成功，不是群成员已读回执。

发送前先持久化本次时段。网络超时、退出或断电导致结果不明时不重发，避免重复刷群。仅执行当前两分钟内的有效时段，停机错过更早的时段不补发；启用时已经过去的时段也不补发。检查间隔约十秒，多群发送会依次排队，不能保证精确到秒。

状态文件损坏时停止发送并保留原文件；每个群任务只保留最近 8 条结果及轮换进度。定时发送复用现有 QQ 进程，关闭进程时一并停止，不会另开一个 QQ 网关。

官方说明：[消息收发概述](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)、[发送群聊消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)。
