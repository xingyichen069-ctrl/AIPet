# 旧安装迁移

更新 main 时，先把新版解压到独立新目录，再复制私人资料。**保留整份旧安装，确认新版可用后再决定如何存放旧版。** 本文说明 Windows 的“迁移私人内容.bat”；macOS 的实验性入口见 [README](../README.md#macos实验性)。

普通安装迁移会保留已有的人格、边界和参数，不会把新版公开模板套到私人文件上。可选的人格格式候选导出是另一项操作，见本文末尾。

## 按这个顺序更新

1. **退出旧桌宠和旧 QQ。** 从桌宠菜单退出；若启用了 QQ、开机启动或其他独立后台组件，也先停止。关闭桌宠窗口不等于 QQ 已停止，QQ 的停止和状态确认见 [QQ 接入](QQ机器人接入提示词.md)。迁移窗口不会替你结束任何进程，迁移期间不要再使用两份安装。
2. 从 [main 下载源码 ZIP](https://github.com/xingyichen069-ctrl/AIPet/archive/refs/heads/main.zip)，完整解压到新的可写目录。例如旧版是 `D:\AIPet-old`，新版放在 `D:\AIPet-new`。不要覆盖旧目录，新旧目录也不能互相包含。本仓库另有开发分支；程序原有“检查更新”会比较全仓标签，不能据此确定标签属于 main。
3. 在**新目录**双击 **准备环境.bat**，等待环境准备与本地配置检查完成。它只补齐缺失的 `config.json`、`thinking.json` 和 `secrets.json`，不会提前生成人格。**此时不要填写新密钥、编辑新配置或启动桌宠。** 空模板不会阻止迁移；已填写的配置或新生成的私人资料会让迁移窗口拒绝覆盖。
4. 如果旧版启用了自定义 Live2D 模型，先按旧 `data/config.json` 中 `live2d.model` 的位置，把**完整模型文件夹**复制到新目录相应位置。不要只搬一个 `.model3.json`，也不要为补模型把整份旧 `data` 覆盖过去。普通内置模型无需这一步；其他手动补齐项见下表。
5. 在**新目录**双击 **迁移私人内容.bat**，选择实际使用的旧安装根目录，即包含 `src`、`data` 的那一层，而不是 `src` 或 `data` 本身。确认窗口会显示来源、目标、文件数量、类别及注意事项；核对后再确认复制。
6. 等待完成提示。出现“已复制，但配置还需检查”时，资料已经复制到新目录，应按提示修正新目录中的配置，再运行 **检查配置.bat**；这条提示不表示已经自动撤销复制。其他失败情况见下文。
7. 在两边程序仍停止时补齐所需的群档位、自定义资源等，再启动新版逐项核对。确认能使用后，从新目录重新创建桌面快捷方式，并检查开机启动项是否仍指向旧目录。

“迁移私人内容.bat”本身也会检查和准备新环境。先运行“准备环境.bat”便于把依赖下载问题与资料迁移分开处理；不用提前为新版再填一遍 API 密钥。

## 会自动复制什么

只复制下表中**实际存在的文件**。没有使用过的可选功能不一定有对应文件，缺少这些文件会跳过。

| 内容 | 复制范围 |
|---|---|
| 人格与当前选择 | `persona/` 顶层的 Markdown 文件、整个 `persona/characters/`、`persona/active.json`；人格目录内的头像和其他资源也在范围内 |
| 记忆 | `memory/` 下的文件，包括人物记录、时间线、摘要和归档 |
| API 与 QQ 凭据 | `data/secrets.json`，以及 QQ 的 `data/qq_token.json` 缓存 |
| QQ 绑定与会话资料 | `data/qq.json`、`data/qq_history.json`、`data/qq_media/` 下的文件；最近会话记录不等于完整聊天存档 |
| 配置与档位 | `data/config.json`、`data/thinking.json`；保留原有档位、模型和参数 |
| 外观和界面状态 | `data/appearance.json`、`data/desktop_ui.json`、`data/pet_state.json`，包括主题偏好、话题草稿、附件快照和窗口状态 |
| 情绪方案与状态 | `data/persona_moods.json`、`data/moods/` 下的文件、`data/mood_catalog.json`、`data/mood.json`、`data/mood_log.jsonl`；人格自带的 `MOODS.json` 随人格库复制 |
| 对话、约定和陪伴 | `data/companion.sqlite3` 数据库 |
| 默认位置的知识库 | `knowledge/` 下的资料和 `data/knowledge_index.json` |
| 历史 ZIP 备份 | `backups/` **顶层**的 `*.zip`；不包含子目录中的 ZIP 或目录型备份 |

QQ token 是客户端管理和刷新的缓存，不是需要重新手填的配置；正常更新不必手工改名或编辑它。复制成功也不代表 QQ 已完成认证，仍需在新目录单独确认连接和实际回复。认证异常时按 [QQ 接入](QQ机器人接入提示词.md) 排查。

## 需要手动补齐或重新确认的内容

| 内容 | 如何处理 |
|---|---|
| **QQ群的单独档位** | 当前清单遗漏 `data/qq_group_levels.json`。如果要保留每个群的覆盖设置，在旧、新 QQ 都停止时，把这个文件复制到新目录的同名位置；也可在迁移后重新设置。未补齐的群默认跟随桌面档位，`/档位 跟随` 可清除本群覆盖。 |
| 自定义主题、立绘和模型 | 修改过的 `themes/`、`assets/` 和其他模型目录不会自动复制。按实际修改逐项补齐，保留新版所需文件；`data/appearance.json` 中保存的主题偏好不包含自定义主题本体。人格库内的头像已随 `persona/characters/` 复制，无需再补一遍。 |
| 自定义知识库目录 | `knowledge.docs_dir` 的自定义位置不会额外复制。确认原资料仍可访问，或手动复制后在新配置中改到正确位置。资料、路径有变化时重建索引，步骤见 [工具与沙箱](工具与沙箱.md#本地知识库)。 |
| 文件沙箱与外部文件 | `tools.fs_root` 原值会保留，沙箱中的外部资料不会另行复制。绝对路径可能仍指向旧目录或原文件夹；需要核对，并在改位置后更新新配置。草稿里的附件路径也要检查。 |
| 目录型或多层历史备份 | 不在顶层 `backups/*.zip` 范围内的备份要自行留存。迁移不删除旧备份。 |
| 环境与系统设置 | 新目录单独准备 `.venv` 或完整 `runtime`，不要把复制旧 `.venv` 当作安装步骤。项目 `.python`、系统环境变量、系统代理配置也不会由迁移窗口搬运或重设。API 环境变量仍可能优先于已复制的密钥文件。 |
| 快捷方式、开机启动和计划任务 | 迁移窗口不会自动改路径。先确认新版正常，再把需要使用的入口改到新目录，避免开机又启动旧 QQ。 |
| 自改代码和其他文件 | 旧 `.bat`、源码修改及清单外的自建文件不会自动合并。逐项比较后决定是否移植，不要用旧源码覆盖整份新版，也不要补拷整个旧 `data` 目录。 |

`data/cache/`、`data/qq.log`、`data/qq.pid`、`data/qq_status.json`、生成的 `view/` 和 Python 字节码不复制。它们不能用来判断新目录的 QQ 是否在线。新安装的公开代码、模板及内置资源来自新版 ZIP。

## 为什么迁移会停下来

| 提示或情况 | 含义与下一步 |
|---|---|
| 找不到安装，或新旧目录重叠 | 两边必须是包含 `src/pet.py` 的安装根目录，且新旧目录不同、互不包含。重新选择目录。 |
| 新目录已有私人内容 | 已编辑的配置、人格、记忆、会话等可能被覆盖。保留这份目录，另解压并准备一份干净新版；不要用强制覆盖跳过判断。 |
| 旧目录只有公开模板 | 没找到可识别的私人资料。确认选的是平时实际启动的旧安装，而不是刚下载的源码包。 |
| 旧配置的 `paths` 不受支持 | `paths` 下任何非说明字段与新版公开模板不同都会阻止双击迁移，**不只检查记忆位置，`view` 等路径也在内**。先人工确认这些文件的来源和新位置；普通流程不能保证迁移这种布局。 |
| 启用中的自定义模型找不到 | 按 `live2d.model` 复制完整模型目录后重试。这里只检查模型入口文件是否存在，不验证纹理、动作等资源齐不齐；复制后仍要实际显示角色确认。 |
| Live2D 已关闭，但自定义模型缺失 | 会提示后继续，未使用的模型不会自动补齐。将来开启 Live2D 前仍需准备模型。 |
| 配置 JSON 无法读取 | 旧 `config.json`、`thinking.json`、`secrets.json` 必须能解析成 JSON 对象；部分路径字段也会预先检查。按具体错误修正后再试，完整字段检查在复制后继续进行。 |
| 文件变化、数据库被占用或校验失败 | 退出使用旧资料的程序再试。不要删原数据库；持续失败时保留旧安装，并在副本上排查。 |
| 路径通过链接指向安装外 | 匹配到的资料路径、目标位置，以及新目录的 `work`、`backups` 都不能绕到安装外。需要先人工确认链接与真实资料位置。 |

自定义知识库目录和非空的 `tools.fs_root` 通常只显示提醒，不会因路径本身而停止。Live2D 的绝对路径也可能继续指向外部甚至旧目录；“没有报错”不等于新版已经摆脱旧资源路径。

## 迁移后确认

1. 运行 **检查配置.bat**。它只做本地格式和部分字段检查，不验证 API 密钥有效性、账户额度、QQ 平台权限或模型资源完整性。
2. 启动新版，查看当前人格、私人 SOUL 与边界是否正确，检查历史话题、草稿、约定和需要保留的情绪方案。普通迁移保留原文件；不会因公开默认模板更新而自动重写它们。
3. 核对档位、模型、主题、立绘、知识库和文件沙箱，发一条对话确认大脑 API 能回复；使用看图或文件功能的，再分别确认对应能力。
4. 使用 QQ 的，确认旧 QQ 已停止，再从新目录启动，检查绑定、群档位和实际消息回复。桌面对话成功不能代替 QQ 接入验证。
5. 退出并重新启动新版一次，确认仍是新目录、当前人格和刚才的话题。检查桌面快捷方式及开机启动位置。

## 失败时怎样回退

迁移先在新目录的 `work/migration-*` 暂存并校验文件，再写入目标；对话数据库使用 SQLite 备份快照，包含已提交但尚未并入主文件的数据。需要覆盖的新目录文件会先保存到 `backups/迁移前-<时间>-<编号>/`，其中的 `manifest.json` 记录本次复制。

**这份备份保存的是新目录被覆盖前的文件，不是旧安装的完整备份。** 正常新目录流程中，它主要是空配置模板；其他使用方式下也可能含密钥，不要把整份迁移备份公开发送。普通 ZIP 备份与迁移的范围不同，见 [备份与恢复](备份与恢复.md)。

- 写入时出现可捕获的错误，程序会尝试恢复本次覆盖的文件、撤回本次新增文件；回退失败会在记录中标为 `rollback-incomplete`。不能把这理解为断电、强制结束进程等情况下都能自动完整恢复。
- “已复制，但配置还需检查”属于复制后的配置问题，不会自动回滚。保留新目录，按提示修正；已经有私人资料的新目录不能再直接作为空目标重新迁移。
- 需要继续使用旧版时，先退出新版桌宠和新版 QQ，再从保留的旧目录启动。双击迁移入口只复制资料，不删除旧安装。
- 迁移后在新版产生的新对话、约定或修改不会自动合并回旧版。回退前保留新版目录，避免丢掉这部分新增内容；两份安装不要同时使用同一套外部资料。

## 普通迁移与人格候选转换

`tools/migrate_persona_runtime.py` 是**可选的旧人格格式检查与候选导出工具**，不是上述安装迁移步骤，也不迁移整份安装。它读取旧人格，向工具所在的新项目 `work/persona-runtime-candidates-*/` 导出候选、差异和清单，供人工查看；旧 `--apply` 已停用，不能自动改写私人 SOUL 或档位参数。

需要调整人格时，先完成普通迁移、保留原文件，再阅读 [人格运行时调整](人格运行时调整.md#旧安装迁移) 和 [人格管理](人格管理.md)。不要把候选目录整包覆盖到私人资料上。

## 进阶命令行入口

日常更新优先使用双击窗口。`tools/migrate.py` 仍有独立命令行入口，但**不执行窗口中的全部自定义路径、模型和配置兼容性预检**，不能把两者当成完全相同的操作。

若只想预览复制范围，可在**新目录**的命令提示符中运行（路径换成自己的旧安装）：

```bat
.venv\Scripts\python.exe tools\migrate.py "D:\AIPet-old" --dry-run
```

完整便携环境把解释器改为 `runtime\python.exe`。`--dry-run` 在复制和旧进程处理前退出，不会搬文件或停止 QQ。

直接执行实际命令行迁移时，默认会尝试识别并停止旧 QQ 桥，还可能清理旧 `data/qq.pid`；这与**从不结束进程**的双击窗口不同。命令行还能提示部分旧快捷方式，但不会修复它们。不要为绕过窗口的拒绝提示而直接加 `--force`，也不要把 `--with-runtime` 当成新环境准备的替代方案。
