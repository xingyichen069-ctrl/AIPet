# 记忆系统

本版修复的是回忆读取、预算和本轮工具参数。存储完整性、撤回范围、压缩与整理仍有未解决问题，详见下文；不要把它们作为首次安装后的必做维护。

## 资料放在哪里

| 文件 | 用途 |
|---|---|
| `persona/PROFILE.md` | 长期档案文本，不一定在新装时存在；人工或外部整理流程维护 |
| `memory/journal.jsonl` | 事件与事实条目，记录时间、重要度、情绪、衰减类别及说话人等 |
| `data/companion.sqlite3` | 桌面话题、双方消息、约定等；不是journal的替代品 |
| `memory/summaries/`、`memory/archive/` | 手动压缩产生的摘要与原文归档；当前未接回普通对话检索 |

以下是默认路径。不要为了初始化去删除journal、档案或数据库；首次启动会创建需要的运行资料。更新按[README](../README.md#从旧版本更新)搬到干净新目录。

## 对话怎样选取回忆

相关性评分结合关键词、重要度、时间衰减、标签和说话人权重。中文采用单字、相邻二字等特征；没有向量服务，也不保证能理解所有改写问法。

| 衰减类别 | 默认系数 | 含义 |
|---|---|---|
| `permanent` | 0 | 不随时间衰减 |
| `slow` | 0.004 | 半衰期约173天 |
| `normal` | 0.02 | 半衰期约35天 |

衰减影响检索机会，不会因此自动删除原记录。近期兜底等规则也会影响最终选择，不能把一个热度阈值当作绝对的“不会再出现”。

## 预算与超长记忆

先选按分数排序的命中，再在**剩余条数和预算内**补入阶段事实与近期兜底；没有“最近N条无论如何一定注入”的保证。

- 自动注入与本轮 `recall` 共用已经确定的检索参数快照。中途切档不改变已经开始的一轮，多轮并行不会相互改写检索配置。
- 预算计算程序最终生成的相关回忆块，包含标题、日期、来源、说话人和截取标记；条数也一起限制。
- 超长条目截取为片段，并标注 `［记忆片段已截取，原记录未改动］`。原来的完整journal记录保留，不会因为一轮对话的预算被改写。
- 预算太小、连来源与必要提示都放不下时，该条不会注入。没有相关结果的提示也需容纳在预算内。

这是**本程序的估算token预算**，不是服务商精确计数，也不是整次请求上限。人格、档案、真实聊天历史及其他工具输出另占上下文；知识库使用独立预算。桌面对话按[六档配置](思考强度配置手册.md)覆盖检索默认值，独立调用的默认检索预算在 `config.json`，发行模板为1200。

## 隐私与撤回的当前边界

普通记忆写入会拒绝包含 `privacy.blocked_patterns` 的句子。该过滤不是所有持久化入口的统一保证；本地提醒等路径仍有缺口，修改隐私词后需重启。

撤回/更正目前可能连带影响其他话题或说话人的同文记忆；并发写入和重写journal也存在丢失风险。本轮未修改这些写入链路。历史备份、已整理进PROFILE和已归档的内容不会随着撤回自动全部清除，不能把“撤回并忘记”理解为全盘擦除。

人格与记忆保存在本机，不代表只在本机使用：选中的上下文会随聊天发给已配置的大脑API。保留独立旧目录与[私人备份](备份与恢复.md)，不要将资料包公开分享。

## 压缩与整理：暂缓作为日常操作

现有 `compress` 会把部分旧条目归档并生成周摘要，但仍有三处缺口：

- 摘要和archive尚未接回普通对话，压缩后的内容可能无法再被对话找回。
- 同周分次压缩可能覆盖前一次摘要；月摘要尚未真正生成。
- 已归档后再撤回的内容缺少完整排除跟踪；直接重新接回归档检索可能让已撤回文字重新出现。

因此本轮没有开启归档检索，也没有改压缩和撤回规则。`consolidate.py brief` 只准备整理素材，`done` 推进游标；两步之间新增资料可能被漏过。项目没有内置“每晚23:30自动整理”，不建议新用户为保养资料运行这些命令。

## 查看当前资料

先在项目目录打开cmd；便携安装将解释器替换为 `runtime\python.exe`，Mac用 `.venv/bin/python`：

```bat
.venv\Scripts\python.exe src\memory.py stats
.venv\Scripts\python.exe src\memory.py search "报告"
.venv\Scripts\python.exe src\memory.py context "报告"
.venv\Scripts\python.exe src\render.py --open
```

`context` 用于查看该命令的上下文，不等于桌面所有档位最终请求。`render` 会在本机生成 `view/memory.html` 并打开，面板不用联网加载资源；其中含私人内容。面板排序存在已知问题，不能凭按钮名称认定时间顺序正确。

不要在自己的安装中运行 `demo` 再删除文件“清空测试数据”。开发者验证使用 [隔离测试入口](命令行参考.md#隔离测试)。

## 群里别人说的话

QQ 群里的发言和主人自己的记忆**分开存、分开算**：

| 说话人 | 检索权重 | 重要度上限 | 衰减 |
|---|---|---|---|
| 主人 | 1.0 | 5 | 按 `decay` 字段 |
| 认得的群友 | 0.6 | 3 | 半衰期约 11.5 天 |
| 陌生人 | 0.45 | 2 | 半衰期约 4.6 天 |

群友的记忆注入 prompt 时会带「群里有人说的」前缀，避免模型张冠李戴。**把别人的事记成主人的，不是权重高低的问题，是错的。**

参数都在 `data/config.json` 的 `speaker` 段。
