## 当前接口差异

- `CompanionController.activity()` 把工作状态直接送到 Live2D，完成/失败靠延时回到待机；没有轮次标识。
- `Live2DWidget` 直接把状态写成 Hiyori 参数，点击动作和待机另走 `play()`，没有共同的互斥、过期或恢复规则。
- `ChatWindow` 使用后台 worker 信号，表演侧需要拒绝旧 worker、旧轮次及已取消轮次的迟到事件。
- 画室任务书仍记录 V13 肩手结构待修；它是接口参考，不是本轮要执行的接入指令或已验收资产。

## 实现方案

1. **纯 Python 控制层**：工作状态、基础心情、短动作分别保存；事件白名单、递增轮次、皮套代数/动作令牌隔离旧结果。使用可注入的毫秒时钟，明确动作时限、有限等待队列、打断和恢复规则。
2. **皮套能力映射与渲染适配**：Hiyori 只声明实际存在的动作，喝茶仅在模拟角色中验证。输出参数受映射和实际模型范围共同约束，缺少动作不会伪装成已执行。原有渲染故障回退继续保留。
3. **现有桌宠桥接**：接收回复开始/进度/完成/取消、安静陪伴、点击反馈、拖拽、模型更换/失败及退出事件。只修改事件接线，不改脑模型请求、人格或记忆算法。
4. **离线测试台**：操作按钮、模拟回复、可见状态、事件理由、确定性回放、导出与无界面复核。测试台不导入私人配置、人格、记忆或脑模块；原生 Hiyori 预览为独立可选入口。

## 决策与验收要求

- 程序生命周期/关闭优先；拖拽、安静与暂停阻止短动作。用户明确动作高于回复动作，回复动作高于自动反馈。被打断的短动作取消，松手/恢复时返回当前工作状态和基础心情，不继续半截旧动作。
- 连续动作请求采用容量受限且会过期的等待队列；重复请求不无限堆积。每项动作都有截止时间，原生结束回调只是可提前结束的通知。
- 心情变化终止旧短动作，短动作结束不改写基础心情。未支持的能力报告拒绝/降级，不随意映射为其他动作。
- 语言侧只允许白名单中的低频心情/动作意图；原始回复文本不进入控制日志。当前不实现自然语言情绪推断，也不让模型控制参数、路径、优先级、窗口或代码。
- 事件记录包含版本、映射快照、相对时间、输入和计算结果；回放重新计算，不信任文件自带的结果。超限或损坏记录明确拒绝，不能把截断日志当成完整回放。
- 覆盖迟到消息、取消、超时、重复/过量请求、缺少能力、拖拽和暂停打断、皮套切换、原生回调过期、参数复位与限幅；再执行现有完整隔离回归与 Windows 原生检查。
