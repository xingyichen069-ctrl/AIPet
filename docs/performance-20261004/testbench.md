# 工作包 2：离线测试台与可复核记录

2026-10-04。依赖 [工作包 1](controller.md) 的纯控制器与能力映射。测试台不导入 brain、memory、人格或桌宠的私人配置入口，不需要 API key；模拟回复由按钮和内置事件生成。

## 启动

完成 README 中的环境准备后，在项目根目录运行。PowerShell 示例：

```powershell
& .\.venv\Scripts\python.exe -X utf8 -B tools/performance_lab.py
```

便携环境将解释器替换为 `.\runtime\python.exe`；在已经安装 PySide6 的其他环境中运行 `python tools/performance_lab.py` 即可。示意角色不需要 Live2D SDK；原生 Hiyori 预览需要现有 live2d-py、OpenGL 和仓库内的 Hiyori 运行时资源。原生预览失败会回到示意绘制并显示原因。

## 推荐先试的过程

1. 保持“模拟角色”，点击“开始新一轮”，设置基础心情为“开心”。
2. 选择“喝茶”并播放。工作状态仍单独显示为“思考中”。
3. 点击“开始回复”：工作状态更新，但短动作继续。
4. 按住角色或“按住模拟拖拽”：喝茶取消；松手恢复当前工作状态与开心心情。
5. 试安静、暂停和取消本轮，观察事件表中的接受/拒绝理由。
6. 导出记录，再导入核对；播放、暂停、拖动时间条以及 1/2/4 倍速都重新计算事件。

右侧显示工作状态、基础心情、临时动作、队列和当前显示层。表格显示最近 60 条决策，便于读出“为什么没有执行动作”。较矮窗口的右侧控制区可滚动，记录表也可滚动。“设置基础心情”按钮左侧是下一次要发送的值，实际状态以“当前状态”区为准。

切到“Hiyori 现有能力”后，喝茶请求会显示“不支持”；勾选原生预览才能看到实际 Hiyori。纯示意绘制用于理解调度，不能据此确认某个真实模型已经有该动画。

“新建记录”会丢弃本窗口内未导出的记录，旧文件保留。“载入示例”“回放当前记录”“导入并核对”进入回放模式后，手动事件控制禁用；新建记录才返回手动操作。导入失败会保留当前未导出的记录。

## 六个内置示例

| 名称 | 无界面参数 | 检查的行为 |
| --- | --- | --- |
| 一轮正常回复 | reply | 思考、工具、回复、完成、恢复基础心情 |
| 喝茶被拖拽打断 | interrupt | 被取消的动作不补播，恢复最新工作状态 |
| 旧回复迟到 | late_reply | 取消后旧轮次不能污染新轮次 |
| 连续动作与等待过期 | queue | 重复拒绝、队列容量、过期丢弃 |
| 换皮套与旧动作回调 | skin | 能力变化、无喝茶能力、旧动作完成通知无效 |
| 安静、暂停与恢复 | quiet | 临时动作被清除，解除后恢复基础状态 |

## 导出格式与核对含义

`src/performance_trace.py` 负责记录和回放，`src/performance_scenarios.py` 提供示例，`src/performance_lab.py` 是界面，`tools/performance_lab.py` 是入口。

JSON 包含：trace_version、controller_version、初始能力映射快照、相对时间输入事件、结束时间，以及可选的 expected。自动导出的 expected 含最终状态和全部决策的 SHA-256 摘要。以后若修改调度行为或格式，需要更新版本兼容策略，不能把旧摘要失配悄悄当作通过。

回放不直接使用文件内的最终状态，而是从初始映射重新计算全部事件，再逐项核对最终状态和决策摘要。即使某个很早的事件没有改变最终画面，摘要仍能检测出决策差异。摘要用于一致性检查，不是签名，也不证明文件来源可信。

没有 expected 的手写记录可以导入，但界面会说明“原记录无预期结果，已重新计算”；不宣称已对照原结果验证。GUI 在替换当前记录前会先跑完整核对，随后才能寻址或倍速播放。失败的导入不会覆盖当前现场。

为可完整导出而设置的边界：

- 单份记录最多 10000 个输入事件、24 小时相对时间，文件最多 2 MiB。
- 输入事件和映射预留 256 KiB 给输出状态及文件外壳，因此可能在达到 2 MiB 前报告容量不足。
- 控制器默认可见历史 512 条；旧可见行滚出不会丢失其决策摘要。测试台仍保留完整输入事件，达到上限时明确拒绝，不截断后冒充完整记录。
- 时间不得倒退；同一毫秒可以有多个事件，按记录顺序处理。期限先于同时间输入处理。
- 文件读取限制大小；拒绝重复 JSON 字段、非法版本、NaN/Infinity、未知事件/字段、无效编码和过深嵌套。
- 导出先写同目录临时文件，刷新后原子替换；写入/替换失败不会截断已有目标文件。

窗口没有自动保存。长时间连续操作应主动导出并新建记录。这里只记录有限状态事件和能力映射，没有聊天正文字段；普通聊天的既有保存行为不由这个测试台管理。

## 无界面核对

以下入口只用 Python 标准库，不需要 Qt、原生模型、窗口或网络：

```text
python tools/performance_lab.py --scenario late_reply
python tools/performance_lab.py --check work/performance-traces/performance.json
python tools/performance_lab.py --check work/performance-traces/performance.json --report work/verification/replay-result.json
```

指定 `--report` 时，目标的父目录需要已存在。成功返回退出码 0，JSON 中 `ok=true`；失败返回 1 和原因。`expected_verified=true` 才表示文件带有预期结果且核对一致。默认导出位置是本候选的 `work/performance-traces/`，这些实验文件不进入 Git。

## 回放能证明什么

回放核对的是控制决策，不是 GPU 逐帧视频。原生完成通知若在实时记录中出现，也会作为事件录下，但回放不会再次请求原生动画库重现其时刻。回放模式始终使用示意绘制，原生预览按钮禁用；退出/重置会退休旧预览并拒绝它的迟到信号。

这一工具可在皮套未完成时验证“何时播放、被谁打断、之后恢复什么”，也能在交接时附上可复核事件。真实灵梦表情和动作质量、实际语言意图质量、语音口型和多设备长时稳定性需要后续独立验收。
