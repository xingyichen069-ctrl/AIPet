# QQ 内置通道接入

AIPet 自带 QQ 通道，直接连接 QQ 网关，再调用与桌宠相同的 `brain.py`、当前人格和记忆。**不需要 Cherry Studio，不需要外部 MCP，也不用再粘贴一份角色提示词。** 本文件保留旧文件名，内容已于 2026-10-01 按当前 main 更新。

## 准备好两项配置

先按 [README](../README.md) 完成环境准备、大脑 API 配置，并确认桌面对话能得到回复。QQ 连接和大脑接口是两套凭据：

| 字段 | 从哪里取得 | 用途 |
|---|---|---|
| `deepseek_api_key` 等大脑字段 | 你使用的大脑服务商 | 生成回答，沿用桌面配置 |
| `qq_appid` | QQ 开放平台的机器人 AppID | 标识要连接的机器人；值保留英文双引号 |
| `qq_secret` | 同一机器人的 AppSecret | QQ 身份验证，不是个人 QQ 密码或大脑 API key |

在 QQ 开放平台开通所需的群聊或私聊能力，并按控制台完成可用范围配置；普通个人 QQ 账号不是这里的机器人凭据。平台权限或账号资格以你的控制台为准。

双击 **配置API.bat** 打开本机 `data/secrets.json`，填写新模板中的 `qq_appid`、`qq_secret`。旧安装如果没有这两个字段，在最外层对象中补上：

```json
{
  "qq_appid": "你的机器人AppID",
  "qq_secret": "你的机器人AppSecret"
}
```

**上面只展示 QQ 字段，不是整份 secrets 文件。** 保留已有大脑、视觉和其他字段，在相邻字段之间加英文逗号，最后一项不加逗号。可对照公开的 [secrets.example.json](../data/secrets.example.json)，不要用空模板覆盖填好的文件。密钥只存本机，不要发到群里或提交 Git。

运行 **检查配置.bat** 可检查 JSON 等本地配置；它不验证 QQ 凭据是否有效，也不验证 QQ 平台权限。仅使用桌面功能时，QQ 两个字段可以留空。

## 启动、停止与确认连接

1. 确认同一机器人的旧安装或其他客户端已停止，避免多个客户端同时处理消息。新用户无需安装或启动 Cherry Studio。
2. 双击本目录的 **启动QQ.bat**。QQ 是独立后台进程，启动桌宠不会自动启动它，关闭桌宠窗口也不会停止它。
3. 使用 **查看状态.bat**，或查看桌宠右键菜单中的 QQ 状态。进程存在只说明程序在运行，还需确认网关已连接。
4. 在已配置可用的群里 **@机器人并发送一句话**，或向它私聊，确认实际收到回答。
5. 停止时双击同一目录的 **停止QQ.bat**。改源码或 QQ 凭据后，停止再启动；搬到新目录时，分别确认旧、新目录对应的进程和启动项。

需要看报错时，在项目文件夹地址栏输入 `cmd` 并回车。先停止已运行的 QQ，再在该窗口运行：

```bat
.venv\Scripts\python.exe src\qq_bridge.py run
```

完整便携环境把解释器改为 `runtime\python.exe`。这条命令会真正联网并回复 QQ 消息；调试完按 Ctrl+C 退出。不要一边保留后台进程，一边反复启动调试进程。

后台控制命令及自启入口见 [命令行参考](命令行参考.md#qq)。macOS 的整体安装仍属实验性；本页的双击入口和开机自启说明面向 Windows。

## 让它认出你

原生通道能读取发送者的 openid。昵称或一句“我是主人”本身不会授予主人身份，需要用本地生成的一次性口令绑定。

在本机项目目录的命令提示符中运行：

```bat
.venv\Scripts\python.exe src\people.py claim
```

将显示的口令用于与机器人的**私聊**，发送 `认领 口令`，收到确认后再使用需要主人身份的指令。当前口令有效期为 30 分钟。不要把真实口令作为日常消息公开分享。

私聊认证后，发送者 openid 相同的群会识别为主人；不同场景的 ID 不应假定必然相同。若某个群仍未识别，可重新生成口令，在该群 @机器人发送 `认领 口令`，为该群绑定。新口令只交给要认领的本人，绑定完成后检查结果。身份设置保存在本机 `data/qq.json`，更新时按迁移指南带走。

## 人格、记忆和档位

- **人格**：读取人格管理中设为当前的角色，优先使用 `persona/characters/<id>/`。编辑保存或确认导入同一角色的 SOUL 后，后续对话读取更新内容；无需修改外部提示词。进行中的一轮仍使用开始时确定的角色。操作见 [人格管理](人格管理.md)。
- **记忆**：QQ 直接组装当前档案、相关回忆和真实聊天历史。普通生成回复被平台接受后，桥接层尝试将已认证主人的对话写入主记忆，未认证发送者的发言写入对应人物卡的短期笔记。指令、超时或发送失败不走这次追加；最近会话历史另行记录。工具写入与权限仍有待审查边界，详见 [记忆系统](记忆系统.md#qq-中的身份与记忆)。
- **档位**：群聊和私聊默认跟随桌面，群聊不再强制 daily。新装桌面默认 max；更新保留原值。任一群成员可用 `/档位 daily`、`/档位 max` 等设置本群，用 `/档位 跟随` 清除本群覆盖；私聊只有已认证主人能改全局档位。
- **可选功能**：QQ 附件沿用视觉服务配置，具体权限和工具还受所选档位影响。当前知识库的自动参考资料注入仅接入普通桌面和 brain 命令行，QQ 自定义 system 路径未接入；配置外部 MCP 不能自动补上这一项。

## 当前代码仍有的发送处理

旧文档把早期遇到的情况写成了 QQ 平台永久硬限制，这些结论不再作为本指南依据。**当前 main 的本地处理仍需与平台规则分开看**，修改文档不会自动取消代码中的处理：

| 本程序当前行为 | 影响 |
|---|---|
| 一轮回复处理预算为 240 秒；发送时还检查原消息年龄是否超过 240 秒 | 排队、读附件或生成耗时较长时，当前代码仍可能放弃回复 |
| 提示模型尽量在 300 个中文字以内回复；发送前按 1000 UTF-8 字节截取 | 长回复仍可能被本程序截短 |
| 发送前移除 URL 和部分 Markdown 标记、整理空白 | 链接或格式可能没有出现在收到的消息里 |
| 同一会话待处理队列最多保留 5 条 | 忙时继续发消息可能挤掉最早的等待项；这不是总会话轮数上限 |
| 临时历史有条数和闲置时间控制 | 不会把全部 QQ 聊天记录一直装入每轮请求；这不是平台禁止继续聊天 |

底层另保留同一消息 ID 最多 5 次的回复计数，仅在调用者传入去重计数器时生效；当前桥的普通回复没有传入该计数器。不能把它写成“QQ 只能聊 5 轮”。这些代码是否一并调整另行确认，本次接入文档不声称已经取消全部本地处理。

## 常见情况

| 看到的情况 | 先检查什么 |
|---|---|
| 提示没配齐 QQ 凭据 | 检查 `secrets.json` 最外层的 `qq_appid`、`qq_secret`，两项都要填写 |
| 后台进程在，但没有连上 | 查看状态和本机 `data/qq.log` 的连接错误；进程存在不等于认证成功 |
| 网关已连接，消息没有回复 | 检查平台可用范围、群内是否 @、大脑 API 配置，以及日志中的排队、超时或发送错误 |
| 人格还是旧的 | 检查实际运行目录、人格管理中的“当前”标记；不要只修改旧的 `persona/SOUL.md` |
| 档位和桌面不同 | 在对应群发送 `/档位` 查看；需要恢复跟随时发送 `/档位 跟随` |
| 更新后又启动了旧 QQ | 检查快捷方式、开机启动项和进程路径；按 [旧安装迁移](旧安装迁移.md) 操作 |

日志和状态可能包含私人消息、身份标识和路径。排查时只提供必要的报错片段，避免公开整份 `data` 目录。不要在真实安装中用旧 selftest 作为连接检查；开发验证使用 [隔离测试入口](命令行参考.md#隔离测试)。
