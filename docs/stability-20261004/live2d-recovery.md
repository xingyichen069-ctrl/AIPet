# Live2D 故障回退与恢复

工作包日期：2026-10-04。基于 main 的 `c0da0943e795f5682d715315d3d97a17f7a967d3`，版本仍为 `0.5.0-beta.2`。本项与更新来源修复没有代码依赖，可单独提取；没有接入灵梦资产或新增语言/回复表演控制。

## 用户能看到的变化

以前初始化或绘制报错只写日志，父窗口仍然认为 Live2D 存在，既不画静态形象，也无法重新加载初次失败的模型，桌宠可能变成透明窗口。

现在入口文件、moc3 或纹理缺失会在调用原生模型前被发现；初始化、缩放画面或绘制抛出异常时停止该组件，显示静态形象并说明原因。静态形象继续支持点击、双击对话、拖动和菜单；故障时解除鼠标穿透。已有静态 PNG 无法读取时使用内存中的占位图，不覆盖原文件。状态保存或故障组件清理报错也不阻止界面回退。

启用了 Live2D 的安装始终保留“重试”入口：右键 → 高级，以及托盘 → 重试 / 重载 Live2D。修复同一路径的模型资源后可重试；失败组件被移除，重试新建组件。修改配置字段或修复 Python 依赖后仍需重启，按钮不会重新读取整份配置或安装依赖。

健康模型的替换采用先验证后切换：候选加载、设置尺寸、更新并完成一次绘制后才替换原模型。任一步抛出异常就释放候选，继续显示原模型。成功后同步已有的思考档位、安静陪伴和活动状态，不修改状态算法。

## 实现边界

- `src/live2d_widget.py`：增加 `render_ready`、`render_failed` 信号。首次成功绘制才通知可用；一次故障只通知一次并停止帧定时器，避免每帧重复报错。
- 启动监视器只在组件可见且尚未完成首次绘制时运行。事件循环仍能运行但 5 秒内未建立绘制状态时报告失败；隐藏窗口会暂停监视器。它不能中断阻塞在原生调用里的线程。
- `validate_model_files()` 检查 model3.json、Moc/Textures 引用及核心文件存在且非空；加载时再执行 SDK moc 一致性检查及可绘制部件检查。这不是所有纹理、动作、物理文件的完整格式验证。
- 加载、试画与模型替换在 Qt 的 GL 回调中执行。部分加载失败、替换成功/失败会在当前上下文释放对应模型的渲染器。退出或 Qt 销毁上下文时先取得组件上下文，再释放渲染器与模型引用；不清理其他窗口共享的全局 SDK。
- `src/pet.py`：故障/成功通知通过队列进入父窗口，避免在 GL 回调栈中删除组件。处理通知前核对发送组件身份，旧组件迟到的消息不能覆盖新的重试结果。所有控制器先完成构造，再启动模型。
- 退出入口和 QApplication 正常退出都停止模型；默认兼容 OpenGL 格式在 QApplication 前设置，即使启动时模型文件缺失，也为稍后的重试准备好格式。

## 验证记录

环境：本机 Windows，Python 3.14.5、PySide6 6.11.2、live2d-py 0.7.0.4。只借用已有解释器与依赖。测试副本包含公开代码、模板、主题、占位图；原生检查使用仓库内 Hiyori 模型，不读取原安装私人资料，不调用大脑 API 或 QQ。

新增 `tests/test_live2d_recovery.py` 的 19 项故障注入检查覆盖：核心资源、异常 manifest、SDK 拒绝/部分加载、首次绘制、无初始化回调、Update/Draw/Resize 异常、旧模型保留、释放顺序、停止幂等、上下文重建、迟到信号、静态像素命中、双击、拖动、缺文件后重试、依赖缺失，以及清理/状态保存/占位图异常。既有菜单用例补验静态回退后的重试入口。

完整隔离回归执行 247 项，245 项通过、2 项跳过，用时 23.220 秒。跳过的是原有备份符号链接用例，原因是当前 Windows 进程无创建链接权限；不是 Live2D 用例跳过。日志：`work/verification/final-tests.log`。

`tests/live2d_recovery_smoke.py` 会在临时公开配置副本中打开自己的真实窗口，检查以下 11 个节点：

1. 缺少模型入口时显示可点击的静态形象。
2. GL 初始化抛出异常后回退。
3. 重试后恢复真实 Hiyori 画面。
4. 替换入口缺失时原模型继续显示。
5. 候选原生模型已加载、设置尺寸失败时释放候选并保留原模型。
6. 正常替换后释放旧模型。
7. 改变置顶窗口标志后仍能显示。
8. 运行中的 Draw 抛出异常后显示静态形象。
9. 运行故障后的再次重试成功。
10. 无初始化模型时启动监视器触发回退（用例将等待缩短到 200 毫秒）。
11. 监视器回退后的再次重试成功。

11 个节点全部通过；5 次渲染器释放均记录并核对了对应的活动 GL 上下文，结束后没有测试追踪到的模型资源遗留。静态与恢复后的画面均取实际窗口/帧缓冲检查非透明像素，并保存图片核对。这是生命周期验证，不是 GPU 显存泄漏测量。原有 `tests/live2d_smoke.py` 的 8 个活动/安静状态显示检查也通过。

原生结果：`work/verification/live2d-recovery-result.json`、`live2d-recovery-smoke.log`；图片为同目录的 `live2d-fallback-*.png`、`live2d-recovered*.png`。证据保留在本机，源码仅提交可复跑用例及本摘要。
