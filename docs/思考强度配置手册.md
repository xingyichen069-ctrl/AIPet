# 思考强度 · 配置手册

> 对应文件：`data/thinking.json`
> 对应面板：`src/pet.py`（桌面上角色旁边那个）
> 对应引擎：`src/thinking.py`

---

## 一、它是什么

桌面上角色旁边有个面板，六个按钮：

```
⟳      ○      ◔      ◑      ◕      ●
自动    省电    日常    认真    深究    极限    雷霆大思考
```

**这不是装饰。** 换档会真实改变六个维度，其中最关键的是**记忆深度**——
档位越高，它真的会去翻越多旧账。

| 档位 | 记忆预算 | 推理投入 | 搜索 | 自检 |
|---|---|---|---|---|
| 省电 | 350 tok / 3 条 | none | 关 | ✗ |
| 日常 | 1200 tok / 12 条 | low | 按需 | ✗ |
| 认真 | 2500 tok / 25 条 | medium | 按需 | ✗ |
| 深究 | 5000 tok / 50 条 | high | 主动 | ✓ |
| 极限 | 9000 tok / 80 条 | max | 总是 | ✓ |
| 雷霆大思考 | 120000 tok / 120 条 | max | 总是 | ✓ |

**实测效果**（同一个问题「报告 考研 睡眠」）：

```
省电 → 想起 4 条
日常 → 想起 5 条
极限 → 想起 9 条
```

## 二、面板怎么用

| 操作 | 效果 |
|---|---|
| 左键单击角色 | 显示 / 隐藏面板 |
| 左键拖动角色 | 移动（面板跟着走） |
| 悬停某个档位 | 下方显示该档详情 |
| 点击某个档位 | 切换，角色气泡里会说一句 |
| 右键角色 | 完整菜单 |
| `Ctrl+Shift+T` | 全局切换面板 |
| `Esc` | 收起面板 |
| 12 秒无操作 | 自动收起（可关） |

面板默认出现在角色**右侧**，贴屏幕边时自动翻到另一侧。
位置会记住，存在 `data/pet_state.json`。

## 三、六个参数详解

每个档位的 `params` 段里有这些字段：

### `model` — 用哪个模型

字符串。写你实际在用的模型标识。

```json
"model": "deepseek::deepseek-flash"
```

**调参建议：** 不同档位可以配不同模型——省电用便宜的小模型，
极限用贵的推理模型。这是省钱最直接的手段。

```json
"frugal": { "params": { "model": "deepseek::deepseek-flash" } },
"max":    { "params": { "model": "claude::claude-opus-5" } }
```

### `reasoning_effort` — 推理投入 ⚠️ 会被压缩

`none` / `low` / `medium` / `high` / `max`

控制它在回答前"想多久"。

- `none` — 关闭思考模式，直接答
- `low` — 快速想一下
- `medium` — 想清楚再答
- `high` — 完整推理，考虑边界和反例
- `max` — 从头推到尾

> **⚠️ DeepSeek 上这五档会塌成三档。**
>
> | 你传 | 实际生效 |
> |---|---|
> | minimal / low | `low` |
> | medium / high / xhigh | **`high`** |
> | max / ultra | `max` |
>
> **所以「认真(medium)」和「深究(high)」在推理强度上是同一档。**
>
> 它们仍然有区别——`max_tokens`（2000 vs 4000）和
> `memory_budget`（2500 vs 5000）都是真的。但如果你想让这两档在
> *思考深度*上也拉开，得把「认真」的 effort 改成 `low`，
> 或者接受这个现实。
>
> 另外：不是所有模型都支持调推理投入，不支持的会忽略这个字段。

**实测验证**（同一个问题，五个档位跑一遍）：

```
档位      thinking  effort  思维链字数   耗时
frugal    关闭       -           0      1.2s
daily     开启      low         54      1.1s
serious   开启      high        12      0.7s
deep      开启      high        86      1.1s
max       开启      max        231      1.8s
```

可以看到 `serious` 和 `deep` 的 effort 都是 `high`——符合上表。
思维链字数会因问题难度浮动，但 `max` 明显投入最多。

### `max_tokens` — 回复长度上限

`300` → `8000`。

**这个不是越大越好。** 设太大会让它有空间啰嗦。
`SOUL.md` 里定义了它话少，但那只是偏好，`max_tokens` 是硬约束。
两个配合才能压住。

### `temperature` — 随机性 ⚠️ 有坑

`0` ~ `2`。默认档 0.75，越高越随机。

- 陪伴聊天：`0.7 ~ 0.9`（要有人味）
- 写代码/推理：`0.3 ~ 0.6`（要准）

**省电档我设了 0.85**，因为寒暄不需要精确，随机一点反而自然。

> **⚠️ DeepSeek 思考模式下这个参数无效。**
> 官方文档原话："思考模式不支持 temperature、presence_penalty、
> frequency_penalty 参数。请注意，为了兼容已有软件，设置参数不会报错，
> **但也不会生效**。"
>
> 也就是说：**只有「省电」档（关闭思考）的 temperature 是真起作用的**，
> 其余四档的值会被静默忽略。
>
> 这不是能绕过的 bug，是模型设计。`brain.py` 在思考模式下干脆不传这个
> 参数——传一个假装有用的值更糟。

### `memory_budget` / `memory_entries` — 记忆深度 ⭐

**这是最重要的一组参数。**

- `memory_budget` — 记忆注入的 token 上限
- `memory_entries` — 最多注入几条
- `memory_floor` — 无论分数高低，最近 N 条一定注入（保证短期连贯）

它直接写进 `memory.py` 的检索配置，所以改这里是**真的会改变行为**的。

**怎么调：**
- 它老是忘记你几周前说过的事 → 调大 `memory_budget`
- 它回复里塞了一堆不相关的旧事 → 调小，或调大 `retrieval.min_score`
- 换了新话题它还揪着老话题不放 → 调小 `memory_floor`

### `search` — 联网行为

`off` / `on_demand` / `eager` / `always`

- `off` — 不搜。不确定就说不知道
- `on_demand` — 需要事实且不确定时才搜（日常推荐）
- `eager` — 任何可能需要外部信息的都先搜
- `always` — 每次都搜，宁可多搜不凭记忆

**成本提醒：** 搜索是额外开销（API 额度 + 延迟）。
`always` 会让每次对话都慢 1-3 秒。除非在做研究，别设 `always`。

### `self_check` — 回答前自检

`true` / `false`

开启后，回答前会回头验一遍：有没有事实错误、有没有漏掉你的真实意图。

**代价是慢，而且是双倍推理开销。** 只在深究和极限档开。

### `verbosity` — 说话篇幅

自然语言描述，会拼进 system prompt。写具体的约束。

```json
"verbosity": "一句话，不超过 20 字"
"verbosity": "3-6 句，可以分点，但仍然不用客服腔"
"verbosity": "完整展开。允许长，但不许注水"
```

**注意第二条**——`SOUL.md` 定义了它的人格，`verbosity` 要跟人格一致。
如果你把深究档写成"详细回答每个方面"，它就会开始列一二三，
和"话不多、不主动列清单"的设定冲突了。

## 四、自动模式怎么调

默认 `current` 是 `auto`：按问题本身判断该用哪档。

**打分规则在 `auto_rules.signals`，命中即加分（或减分）：**

```json
"question_words": { "为什么": 12, "分析": 14, "权衡": 14, "推导": 16 },
"depth_words":    { "仔细": 18, "深入": 20, "想清楚": 22 },
"simple_words":   { "在吗": -30, "几点了": -28, "嗯": -30 },
"code_signals":   { "报错": 18, "死锁": 20, "性能": 16 },
"length_per_20_chars": 6
```

**分数落在哪个区间就用哪档**（`auto_rules.thresholds`）：

| 分数 | 档位 |
|---|---|
| < 8 | 省电 |
| 8 – 25 | 日常 |
| 25 – 50 | 认真 |
| 50 – 75 | 深究 |
| ≥ 75 | 极限 |

**实际测试：**

```
"在吗"
→ 0 分 → 省电        （命中「在吗 -30」，触底为 0）

"帮我分析一下这个并发架构的权衡，仔细想清楚"
→ 104 分 → 极限
   长度+6 · 分析+14 · 架构+14 · 权衡+14 · 仔细+18 · 想清楚+22 · 并发+16
```

**调参方法：**

- 它动不动就切到极限（太贵）→ 把 `thresholds` 整体调高
- 简单问题它也想半天 → 把 `simple_words` 的负分加重，或降低 `frugal` 阈值
- 复杂问题它敷衍 → 把 `question_words` 的权重加大

**查看当前判定：**

```bash
python src/thinking.py auto "你的问题"
```

## 五、自定义档位

档位是数据，不是代码。你可以直接加。

**例：加一个「写代码」档**

```json
"coding": {
  "name": "写码",
  "icon": "⌘",
  "color": "#4ade80",
  "summary": "低温度 + 全记忆",
  "feels_like": "它把键盘拉过去了。",
  "when": "写代码、改 bug、重构",
  "params": {
    "model": "deepseek::deepseek-flash",
    "reasoning_effort": "high",
    "max_tokens": 4000,
    "temperature": 0.3,
    "memory_budget": 3000,
    "memory_entries": 30,
    "memory_floor": 4,
    "search": "eager",
    "self_check": true,
    "verbosity": "直接给代码，解释压到最少"
  }
}
```

然后把它加进引擎的档位表 `src/thinking.py` 的 `LEVELS` 数组：

```python
LEVELS = ["frugal", "daily", "serious", "deep", "max", "coding"]
```

面板会自动多出一个按钮（按钮宽度按数量自动均分）。

**也可以覆盖现有档位**——直接改 `presets` 里对应那段的数字，比重启面板就生效
（有文件监听，改完自动重载）。

## 六、成本估算

以「日常」档为基准的比较（**仅记忆注入部分**）：

| 档位 | 记忆 token | 相对成本 |
|---|---|---|
| 省电 | 350 | 0.3× |
| 日常 | 1200 | 1× |
| 认真 | 2500 | 2× |
| 深究 | 5000 | 4× |
| 极限 | 9000 | 7.5× |

再算上 `reasoning_effort` 和 `self_check` 的额外开销，
极限档单轮成本大约是日常档的 **10-15 倍**。

**省钱建议：**

1. **保持 auto**。它会把大部分寒暄判成省电档，这部分几乎免费。
2. **不同档位配不同模型**。省电/日常用便宜模型，深究/极限才上贵的。
3. **别把 `self_check` 开在日常档**。双倍推理，收益不明显。
4. **搜索加缓存**。`tools.py` 自带缓存，`news` 默认 15 分钟。
   同一件事反复问不会重复请求。

## 七、和记忆系统的联动

这是设计上最关键的一处。链路是这样的：

```
面板点击
   ↓
data/thinking.json  current 字段被改写
   ↓
thinking.apply_to_memory()  把 memory_budget 写进 M.CFG["retrieval"]
   ↓
memory.retrieve()  按新的预算和条数检索
   ↓
注进 prompt 的记忆量真的变了
```

**验证方法：**

```bash
python src/thinking.py set frugal
python src/thinking.py context "报告 考研 睡眠"   # 4 条

python src/thinking.py set max
python src/thinking.py context "报告 考研 睡眠"   # 9 条
```

**注意：** 面板和 agent 是两个进程。面板写文件，agent 读文件。
`thinking.load()` 带了 mtime 缓存，所以面板改完 agent 下次读取就会看到，
不需要重启任何东西。

## 八、和 agent 对接

如果大脑走 Cherry Studio agent（插槽 A），有三种接法。

**接法一：MCP server（推荐）**

`src/mcp_server.py` 是一个零依赖的 MCP server，把 AIPet 的能力
暴露成 agent 能直接调用的工具。

注册：设置 → MCP → 添加 → stdio

```
命令：<你的 Python 路径>\python.exe
参数：<项目目录>\src\mcp_server.py
```

注册后**默认不激活**，需要在设置里手动启用。

挂上之后，agent 每轮对话可以调 `aipet_context(问题)`，一次拿到：

- 当前思考强度档位（也就是面板上你选的那个）
- 关系状态（亲密度、未兑现的承诺、多久没说话）
- 相关回忆（按当前档位的记忆预算检索）
- 用户档案

**这才算把面板真正接进了对话流程。** 在此之前面板只是改了个文件，
没有任何大脑在读它。

9 个工具：

| 工具 | 作用 |
|---|---|
| `aipet_context` | ⭐ 一次拿全 |
| `aipet_recall` | 只检索记忆 |
| `aipet_remember` | 写入一条记忆 |
| `aipet_thinking_get` | 查看当前档位和参数 |
| `aipet_thinking_set` | 切换档位 |
| `aipet_persona` | 读人格设定（SOUL + BOUNDARIES） |
| `aipet_profile` | 读用户档案 |
| `aipet_search` | 联网搜索 |
| `aipet_stats` | 统计信息 |

自检（不需要客户端）：

```bash
python src/mcp_server.py --selftest
```

**接法二：命令行**

agent 有 shell 权限时，直接跑：

```bash
python src/thinking.py context "用户的问题"
```

输出 = 思考强度块 + 记忆块，直接拼进 system prompt。

```bash
python src/thinking.py params      # 看解析后的参数
python src/thinking.py prompt "…"  # 只要思考强度块
python src/thinking.py list        # 档位总览
```

好处是不需要任何新组件；代价是依赖 agent 每次都记得跑。

**接法三：直接读文件**

`data/thinking.json` 的 `current` 字段 + `presets[档位].params`。
适合你自己写代码时用。

### MCP 需要信道吗？

**不需要。这是两件事，解决的问题不同。**

| | MCP server | 信道（IM 通道） |
|---|---|---|
| 解决什么 | 它思考时**读**面板和记忆 | 它主动**找你** |
| 方向 | agent ← AIPet | AIPet → 你 |
| 需要什么 | 本地 stdio，不联网 | QQ/微信/Telegram 等平台凭据 |
| 用在哪 | 你说话，它回答 | 它没事找事、定时提醒 |

两个可以独立使用：

- 只挂 MCP → 它记得住你、受面板控制，但**不会主动开口**
- 只接信道 → 它能主动找你，但**说话不带记忆和人格**（除非同时挂 MCP）
- 两个都上 → 完整形态

**所以想让面板生效，只需要 MCP，不需要信道。**
信道是为了「AI 室友」那个主动性设计才需要的。

## 九、常见问题

**Q：面板打不开 / 角色没出现**
需要 PySide6：`pip install PySide6`。首次运行会在 `assets/` 生成占位形象，不是错误。

**Q：角色挡住全屏游戏**
已知限制。`Qt.Tool` 窗口会被独占全屏覆盖（这是系统行为，不是 bug）。
无边框全屏游戏通常没问题，独占全屏会被挡。
右键菜单可以关「总在最前」。

**Q：想让它点不到（纯装饰）**
右键 → 鼠标穿透。开启后左键点它会直接穿透到下面的窗口，需要从右键菜单关回来。

**Q：换了形象还是显示旧的**
右键 → 重新生成占位形象。或者直接删掉 `assets/character.png` 重启。

**Q：想换真形象**
把透明 PNG（建议 240×240 或更大，正方形）命名为 `character.png`
放进 `assets/` 覆盖即可。Live2D 需要额外的渲染库，当前版本没有集成——
这一版是静态图方案。

**Q：档位切换后角色说的那句话能改吗**
那是在 `thinking.json` 的 `feels_like` 字段里，每个档位一句。
也可以关掉（`notify.announce: false`）。

**Q：auto 判得不准**
看 `python src/thinking.py auto "问题"` 的输出，它会告诉你命中了哪些词、
各加了多少分。照着调 `auto_rules.signals` 的权重。

## 十、参数速查

```
data/thinking.json
├── current                  当前档位：auto | frugal | daily | serious | deep | max | thunder
├── auto_rules
│   ├── thresholds           分档分数线
│   └── signals              打分权重表
├── presets.<档位>
│   ├── name / icon / color  面板显示
│   ├── summary              一句话概括
│   ├── feels_like           换档时气泡里说的话
│   ├── when                 什么时候用这档
│   └── params
│       ├── model            模型
│       ├── reasoning_effort none|low|medium|high|max
│       ├── max_tokens       回复长度上限
│       ├── temperature      随机性
│       ├── memory_budget    记忆 token 上限 ⭐
│       ├── memory_entries   记忆条数上限 ⭐
│       ├── memory_floor     近期兜底条数
│       ├── search           off|on_demand|eager|always
│       ├── self_check       回答前自检
│       └── verbosity        篇幅约束
├── ui
│   ├── appear_on            click | hover | always
│   ├── position             面板方位 right|left|top|bottom
│   ├── offset               间距（像素）
│   ├── auto_hide_seconds    自动收起秒数，0 = 不自动收
│   └── show_shortcut        全局快捷键（当前版本未绑定，见下）
└── notify
    ├── announce             换档时是否说话
    └── announce_style       说话风格约束
```

**关于 `show_shortcut`：** 配置项已留好，但当前版本没绑定全局快捷键
（需要额外装 `keyboard` 之类的库）。目前用点击角色切换面板。
